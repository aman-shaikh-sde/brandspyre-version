# Meta Marketing, Lead Ads, WhatsApp & Instagram Integration Guide
## Production Architecture & Operational Manual (Hardened)

This document provides the definitive architectural, security, and operational manual for the multi-tenant Meta (Facebook/Instagram/WhatsApp) Marketing, Lead Ads, and Campaign Integration within the Brandspyre SaaS CRM platform.

---

## 1. Architecture Overview

Brandspyre implements a hardened multi-tenant SaaS integration with Meta Graph API (v19.0+):

1. **Centralized Platform App & OAuth Flow**:
   - The platform operates with a centralized Meta Developer App (`META_APP_ID`, `META_APP_SECRET`) in `.env`.
   - Organizations authorize Brandspyre through standard OAuth 2.0 without entering sensitive Meta developer app secrets.
2. **Strict Multi-Tenant Isolation**:
   - Every Meta resource (`MetaBusinessAccount`, `MetaAdAccount`, `MetaPage`, `MetaInstagramAccount`, `MetaWhatsAppAccount`, `MetaCampaign`, `MetaAdSet`, `MetaAd`, `MetaLeadForm`, `WebhookEventLog`) is strictly bound to `tenant_id` (ObjectId) and `branchcode`.
   - Tenant context is strictly resolved from the authenticated JWT session (`req.user.tenantId`, `req.user.brcode`). Frontend-supplied tenant IDs are rejected.
3. **Database Encryption & Token Security**:
   - Access tokens, refresh tokens, and app secrets are encrypted at rest using AES-256-CBC via automated Mongoose getters and setters.
   - All API endpoints strictly strip tokens (`-access_token -refresh_token -meta_app_secret -webhook_verify_token`) to prevent token leakage.
4. **OAuth Security & State Management**:
   - OAuth state parameters are generated with cryptographic randomness (`crypto.randomBytes(32)`).
   - Stored in MongoDB via the `MetaOAuthState` collection with an automated 10-minute TTL index (`expireAfterSeconds: 600`).
   - Single-use state enforcement deletes the token immediately upon redemption (`findOneAndDelete`), protecting against replay and CSRF attacks.
5. **HMAC-SHA256 Webhook Signature Verification**:
   - All incoming webhook events verify `X-Hub-Signature-256` against `META_APP_SECRET` using timing-safe buffer comparison (`crypto.timingSafeEqual`) to prevent timing and length attacks.
6. **Fast Webhook Acknowledgment & Asynchronous Processing**:
   - Webhook controller immediately acknowledges Meta with HTTP 200 (`EVENT_RECEIVED`) and delegates processing to the asynchronous background queue via `setImmediate()`, eliminating webhook timeout drops.
7. **Idempotency & Race Condition Protection**:
   - `Lead` collection contains a sparse unique compound index on `{ tenant_id: 1, meta_lead_id: 1 }`.
   - `LeadMappingService.createLead()` catches duplicate key errors (`code: 11000`) and returns the existing lead, ensuring zero duplicate leads even during concurrent webhook bursts.
8. **Custom Question & Response Retention**:
   - All questions and responses from Meta Lead Forms are preserved in `Lead.meta_raw_fields` and `Lead.custom_fields` (e.g. Budget, Preferred City, Property Type).
9. **Incremental Reconciliation Engine**:
   - `MetaReconciliationService` tracks `last_sync_at` per `MetaLeadForm` and queries Meta Graph API incrementally (`last_sync_at - 5 minutes`) rather than querying the entire 24-hour window repeatedly.
   - Implements Graph API cursor pagination (`paging.next`) with a 1,000-lead safety cap.

## 2. Environment Variables & Credentials

Platform operators must set the following environment variables in `Brandspyre_backend/.env`:

```env
# Meta Platform App Credentials
META_APP_ID=your_meta_app_id
META_APP_SECRET=your_meta_app_secret
META_API_VERSION=v19.0
META_REDIRECT_URI=https://api.yourdomain.com/api/meta/oauth/callback
META_WEBHOOK_URL=https://api.yourdomain.com/api/meta/webhook

# Token Encryption (32-character hex or string)
ENCRYPTION_KEY=your_32_character_aes_encryption_key_here

# Cross-Service URLs
FRONTEND_URL=https://app.yourdomain.com
BASE_URL=https://api.yourdomain.com
```

## 3. Meta Developer App Configuration

### Required Meta App Permissions
When submitting the Meta App for App Review, request the following permissions:
- `pages_show_list`: To discover and enumerate Facebook Pages managed by the user.
- `pages_read_engagement`: To monitor page performance and post metrics.
- `pages_manage_metadata`: To subscribe pages to webhooks automatically.
- `leads_retrieval`: To read real-time lead details generated by Lead Ad forms.
- `ads_read`: To fetch ad campaigns, ad sets, ads, and ad account details.
- `ads_management`: To pause, resume, and create ad campaigns from Brandspyre.
- `instagram_basic`: To discover linked Instagram professional accounts.
- `whatsapp_business_management`: To discover connected WhatsApp Business Accounts (WABA).

### Webhook Configuration in Meta App Dashboard
1. Go to **Meta App Dashboard > Webhooks**.
2. Select **Page** from the dropdown menu.
3. Set the **Callback URL** to: `https://api.yourdomain.com/api/meta/webhook`.
4. Set the **Verify Token** to the platform verify token (or tenant-specific verify token).
5. Subscribe to the `leadgen` event field.

## 5. Webhook Ingestion & Deduplication Pipeline

```
[Meta Lead Ad Submitted]
          │
          ▼
POST /api/meta/webhook
          │
          ├─► 1. Verify X-Hub-Signature-256 (HMAC-SHA256 with timingSafeEqual)
          │       └─ If invalid: HTTP 403 Forbidden
          │
          ├─► 2. FAST ACK: Return HTTP 200 "EVENT_RECEIVED" immediately to Meta
          │
          └─► 3. Asynchronous Worker (setImmediate):
                  │
                  ├─► Idempotency Check (MetaLeadSyncLog & Lead unique index)
                  │       └─ If duplicate: skip processing
                  │
                  ├─► Resolve Tenant Context (Lookup page_id in MetaPage collection)
                  │
                  ├─► Fetch Rich Lead Details (GET /{leadgen_id} with page_access_token)
                  │
                  ├─► Preserve Custom Form Questions (meta_raw_fields & custom_fields)
                  │
                  ├─► Explicit Source Attribution (platform === "instagram" ? "instagram" : "facebook_lead_ads")
                  │
                  ├─► Safe Campaign Attribution (formConfig or MetaCampaign match, NO random fallback)
                  │
                  └─► Upsert CRM Lead with Duplicate Catch (err.code 11000 safe return)
                          ├─ Broadcast event on CRM EventBus
                          └─ Update MetaLeadSyncLog status to 'success'
```

## 6. Background Reconciliation Engine

To guarantee zero lead loss due to network interruptions, webhook delivery timeouts, or Meta transient errors, an automated background reconciliation service runs periodically:

- **Cron Schedule**: Runs periodically every 20 minutes (`MetaReconciliationService.start(20)`).
- **Incremental Cursor Sync**: Only queries leads created since `form.last_sync_at - 5 minutes` (with fallback to 24h on initial run).
- **Cursor Pagination**: Automatically traverses `response.data.paging.next` to capture forms with high lead volumes (up to 1,000 leads per execution).
- **Deduplication Protection**: Checks whether `meta_lead_id` already exists in CRM `Lead` collection or `MetaLeadSyncLog` before creating records.
- **Safe Campaign Attribution**: Strictly preserves campaign attribution from form configuration or matched `MetaCampaign`; never assigns random campaigns.
- **Proactive Token Refresh**: Inspects `token_expires_at` across all active integrations and refreshes tokens with less than 7 days remaining.
